# golem CLI — Design Document

## Philosophy

The `golem` CLI follows the same structural logic as a REST API:
**domain resources become commands, HTTP verbs become subcommands.**

Business logic lives exclusively in *command classes* (Command Pattern).
Typer owns argument parsing and dispatch; command classes own behaviour.
`cli.py` is pure wiring — it never contains logic.

## Domain Model

```
┌──────────────────────────────────────────┐
│              ControlPlane                │
│                                          │
│  name: str   (alias, e.g. "local")       │
│  url:  str   (e.g. http://host:9000)     │
│                                          │
│  Persisted in ~/.golem/cli/config.yaml   │
│  One entry is marked "active"            │
└──────────────────────┬───────────────────┘
                       │  1
                       │  (active CP required for agent/chat commands)
                       │  N
┌──────────────────────▼───────────────────┐
│                  Agent                   │
│                                          │
│  id:     str                             │
│  name:   str                             │
│  status: str                             │
│  config: RunnerConfig  ◄──── 1:1 strong  │
└──────────────────────┬───────────────────┘
                       │  1
                       │  N  (weak)
┌──────────────────────▼───────────────────┐
│                  Chat                    │
│                                          │
│  id:         str                         │
│  agent_id:   str  (foreign key)          │
│  created_at: str                         │
└──────────────────────────────────────────┘

┌──────────────────────────────────────────┐
│             RunnerConfig                 │
│                                          │
│  Supplied as a YAML file on agent create │
│  Template generated by:                  │
│    golem agent config init               │
└──────────────────────────────────────────┘
```

### Relationships

| From         | To           | Cardinality | Type   | CLI consequence                                                               |
|--------------|--------------|-------------|--------|-------------------------------------------------------------------------------|
| ControlPlane | Agent        | 1:N         | Weak   | Active CP resolved from `~/.golem/cli/config.yaml`; no structural nesting     |
| Agent        | RunnerConfig | 1:1         | Strong | `--config` is required on `agent create`; `agent config init` writes template |
| Agent        | Chat         | 1:N         | Weak   | `--agent` is a required filter option on all `chat` subcommands               |

**Strong (1:1) → nested sub-group:** `agent config init` lives under `agent config`.  
**Weak → top-level with filter/context option:** `chat` is its own top-level command group.

## CLI Configuration

Persistent state (registered control planes, active selection) is stored in:

```
~/.golem/cli/config.yaml
```

Schema:

```yaml
active: "local"
control_planes:
  - name: "local"
    url:  "http://localhost:9000"
  - name: "prod"
    url:  "https://golem.example.com"
```

If no active control plane is set, any command that requires the API (`agent *`, `chat *`)
fails immediately with a clear message:

```
No active control plane. Run `golem cp use --name <name>` to select one,
or `golem cp add` to register a new one.
```

## Command Design

### Verb mapping (REST → CLI)

| HTTP method         | CLI subcommand | Meaning               |
|---------------------|----------------|-----------------------|
| `GET /resources`    | `list`         | List all instances    |
| `GET /resources/id` | `show`         | Show one instance     |
| `POST /resources`   | `create`/`add` | Create a new instance |
| `DELETE /resources` | `delete`       | Delete an instance    |
| domain-specific     | `status`       | Health/readiness check|
| domain-specific     | `use`          | Set active context    |

### Full command table

| Command        | Subcommand | Options / Args                                                              | Description                                        |
|----------------|------------|-----------------------------------------------------------------------------|----------------------------------------------------|
| `cp`           | `add`      | `--name/-n` (str, req), `--url/-u` (str, req)                               | Register a new control-plane endpoint              |
| `cp`           | `use`      | `--name/-n` (str, req)                                                      | Set the active control plane                       |
| `cp`           | `list`     | —                                                                           | List all registered control planes                 |
| `cp`           | `remove`   | `--name/-n` (str, req)                                                      | Remove a registered control plane                  |
| `cp`           | `status`   | `--name/-n` (str, optional, default: active)                                | Check if a control plane is healthy                |
| `agent`        | `create`   | `--name/-n` (str, req), `--config/-c` (path, req), `--ttl/-t` (int, optional — omit for persistent) | Deploy a new agent sandbox (multipart upload) |
| `agent`        | `list`     | —                                                                           | List all agents                                    |
| `agent`        | `show`     | `--id/-i` (str, req)                                                        | Show agent details                                 |
| `agent`        | `delete`   | `--id/-i` (str, req)                                                        | Delete an agent                                    |
| `agent`        | `status`   | `--id/-i` (str, req)                                                        | Show health/readiness of a running agent           |
| `agent config` | `init`     | `--output/-o` (path, default: `config.yaml`)                                | Generate default runner-config template            |
| `chat`         | `new`      | `--agent/-a` (str, req)                                                     | Create conversation + open interactive WS session  |
| `chat`         | `switch`   | `--agent/-a` (str, req), `--id/-i` (str, req)                               | Resume existing conversation via WS                |
| `chat`         | `list`     | `--agent/-a` (str, req)                                                     | List conversations for an agent                    |
| `chat`         | `delete`   | `--id/-i` (str, req)                                                        | Delete a conversation                              |

### Usage examples

```bash
# --- Control plane management (no active CP required) ---
golem cp add --name local --url http://localhost:9000
golem cp add --name prod  --url https://golem.example.com
golem cp list
golem cp use --name prod
golem cp status
golem cp status --name local
golem cp remove --name local

# --- Generate and customise runner config ---
golem agent config init
golem agent config init --output my-runner.yaml

# --- Agent lifecycle (requires active CP) ---
golem agent create --name "my-agent" --config config.yaml            # persistent (never expires)
golem agent create --name "my-agent" --config config.yaml --ttl 3600 # ephemeral — deleted after 1 hour
golem agent list
golem agent show --id abc123
golem agent status --id abc123
golem agent delete --id abc123

# --- Chat sessions (requires active CP) ---
golem chat new --agent abc123
golem chat switch --agent abc123 --id conv456
golem chat list --agent abc123
golem chat delete --id conv456
```

## Architecture

### Command Pattern

Each domain resource maps to exactly one command class. Typer wrapper functions in `cli.py`
delegate immediately to these classes — they contain no logic of their own.

```
┌──────────────────────────────────────────────────────────────────────┐
│                             cli.py                                   │
│  Typer app + add_typer wiring                                        │
│  Thin @app.command() wrappers → instantiate command class lazily     │
│  (cp commands use a module-level singleton — no active CP needed)    │
└───────────┬──────────────────────┬────────────────────┬─────────────┘
            │                      │                    │
            ▼                      ▼                    ▼
┌──────────────────┐  ┌───────────────────┐  ┌──────────────────────┐
│   CpCommand      │  │   AgentCommand    │  │    ChatCommand       │
│                  │  │                   │  │                      │
│  add(name, url)  │  │  create(...)      │  │  new(agent_id)       │
│  use(name)       │  │  list()           │  │  switch(agent, id)   │
│  list()          │  │  show(id)         │  │  list(agent_id)      │
│  remove(name)    │  │  delete(id)       │  │  delete(id)          │
│  status(name)    │  │  status(id)       │  │  _run_ws_session()   │
└────────┬─────────┘  │  config_init(out) │  └──────────┬───────────┘
         │            └────────┬──────────┘             │
         └──────────┬──────────┘                        │
                    ▼                                    │
           ┌─────────────────┐                          │
           │  Command (ABC)  │ ◄────────────────────────┘
           └─────────────────┘
                    ▲
           ┌─────────────────────────────┐
           │  config.py                  │
           │  load() / save()            │
           │  get_active_url() → str     │
           │  ~/.golem/cli/config.yaml   │
           └─────────────────────────────┘

           ┌─────────────────────────────┐
           │  _agent_config_template.py  │
           │  write_default(output)      │
           └─────────────────────────────┘
```

### Transport layer

| Resource | Transport | Library      | Notes                                         |
|----------|-----------|--------------|-----------------------------------------------|
| `cp`     | local I/O | `pyyaml`     | Reads/writes `~/.golem/cli/config.yaml`; health check via `httpx` |
| `agent`  | REST      | `httpx`      | Multipart form POST for create; JSON for CRUD |
| `chat`   | REST      | `httpx`      | `list`, `delete`                              |
| `chat`   | WebSocket | `websockets` | Interactive terminal REPL for `new`, `switch` |

### Lazy instantiation

`AgentCommand` and `ChatCommand` call `config.get_active_url()` in `__init__`,
so they are instantiated **inside each command function** (lazy), not at module level.
This ensures `golem --help`, `golem agent --help`, and all `cp` commands work with no
active control plane configured.

`CpCommand` does not touch the active URL and is safe as a module-level singleton.

## Key design rules

1. **Domain first.** Entities are resources; relationships determine navigation depth.
2. **Resources → commands. Verbs → subcommands.** Same logic as REST.
3. **Max 2 levels of nesting.** Deeper hierarchies use options, not more subcommands.
4. **Typer dispatches, command classes encapsulate.** `cli.py` is wiring only.
5. **One command class per resource.** Subcommands are *methods* of that class.
6. **No shared `execute(args)` method.** Each method has its own explicit typed signature.
7. **Typed signatures are the spec.** If mypy complains, the design has a gap.
8. **Help text on every command and option.** All `typer.Typer()` apps use `no_args_is_help=True`.
9. **File size discipline.** Keep `*_command.py` files under ~120 lines; extract data blobs
   into private `_<resource>_<concern>.py` modules in the same package.
10. **Lazy instantiation for CP-dependent commands.** Commands that need the active control
    plane are instantiated inside the wrapper function, not at module level, so that `--help`
    and `cp` commands always work regardless of config state.
